# moodle+R UI改善 Chrome拡張 — 要件定義

対象: `https://lms.ritsumei.ac.jp/*`（Moodle 4.x, theme_boost, 表示名 moodle+R）
作成日: 2026-09-06

## 1.1 目的

立命館大学LMS（moodle+R）のフロントエンドを、Chrome拡張のクライアントサイド書き換えのみで改善する。サーバ側・Moodleプラグインには一切手を入れない。

## 1.2 スコープ

| 対象画面 | body#id | 主な改修 |
|---|---|---|
| ダッシュボード | `page-my-index` | 時間割の一覧性、締切順課題ブロック |
| コース画面 | `page-course-view-*` | 種別分類タブ、コースインデックスのツリー化 |

対象外: 課題提出画面、フォーラム個別ページ、成績表、モバイルアプリ。

## 1.3 機能要件

### F1. 時間割の一覧性改善（優先度: 最高）

現状、`section.block_rutime_table` 内の時間割がスクロールを伴い、一覧できない。

原因の想定（要検証）:
- `<body class="limitedwidth">` により本文幅が約830pxに制限される
- 右ブロックドロワが開くとさらに幅が削られる
- 7列に対し1セル約100pxしか確保できず、`52336:財務会計論 (B) § 52337:財務会計論(B)` が5〜6行に折り返される
- 結果として行高が肥大し、**縦方向**に伸びる

| ID | 要件 |
|---|---|
| F1-1 | `/my/` において `.limitedwidth` の幅制限を解除し、時間割ブロックを利用可能幅いっぱいに広げる |
| F1-2 | コース名から先頭の科目コード（`^\d+[:：]`）を除去する |
| F1-3 | コース名が `§` を含む場合、最初の要素のみを表示する（合併クラスの重複表記の除去） |
| F1-4 | 教室表記から曜日時限の接頭辞（`^[月火水木金土日]\d+[:：]`）を除去する |
| F1-5 | `span.off`（消灯アイコン）をDOMから除去する。`span.on` のみをテキスト付きバッジに変換する |
| F1-6 | `.timetable-legend` を非表示にする |
| F1-7 | ~~全曜日が `td.empty` の行、および全時限が `td.empty` の列を自動判定し非表示にする。トグルボタンで復帰できること~~ **【変更・2026-09-07】曜日列は常に全て表示する方針に変更。空の時限行を隠すトグルボタンも機能していなかったため実装ごと削除した（ユーザー指摘）** |
| F1-8 | セルは固定行高 + `text-overflow: ellipsis`、完全なコース名は `title` 属性に保持する |
| F1-9 | 本日の曜日列を背景色でハイライトする |
| F1-10 | 現在時刻が属する時限のセルを枠線で強調する。時限↔時刻の対応表は設定画面で変更可能とする |
| F1-11 | コースIDのハッシュから安定色を生成し、セル左ボーダーに適用する |

**受入基準**: 幅1280px・高さ800pxのウィンドウで、時間割ブロック全体がスクロールなしで表示されること。

### F2. 締切順の課題リストブロック（優先度: 高）

| ID | 要件 |
|---|---|
| F2-1 | ダッシュボードのメイン領域最上部に「課題（締切順）」ブロックを新規挿入する |
| F2-2 | Moodle Web API `core_calendar_get_action_events_by_timesort` を用いて全コース横断で取得する。**取得後、`modulename` が `assign`/`quiz`/`workshop` のイベントのみ表示対象とする**（Phase 0調査でこのAPIがURL・ページ等あらゆる活動の完了予定日も返すことが判明したため。ユーザー確認済み、2026-09-06） |
| F2-3 | 締切昇順で表示する。1行 = 残り時間 / 締切日時 / コース名 / 課題名 / 遷移リンク |
| F2-4 | 残り時間で4段階に色分けする（超過 / 24時間以内 / 7日以内 / それ以降） |
| F2-5 | 期間フィルタ（期限切れ / 7日 / 30日 / すべて）を持つ。既定は30日 |
| F2-6 | 取得結果を `chrome.storage.local` に5分間キャッシュする |
| F2-7 | 取得失敗時はブロック内にエラー表示し、他機能に影響させない |
| F2-8 | 標準の `block_timeline` を既定で非表示にする（設定でOFF可） |

**リスク**: このAPIは「アクション可能なイベント」のみを返すため、提出済み課題の扱いが教員側の完了設定に依存する可能性がある。Phase 0 で実データを確認すること。

### F3. コース画面の種別分類ブロック（優先度: 中）

| ID | 要件 |
|---|---|
| F3-1 | `#region-main` 最上部にタブ（`分類` / `週次（標準）`）を挿入する。既定は `分類` |
| F3-2 | `li.activity` の `modtype_*` クラスで分類する（下表） |
| F3-3 | 各カテゴリはアコーディオン。件数をヘッダに表示する |
| F3-4 | 各項目には元の週セクション名を薄字で併記する |
| F3-5 | 未提出課題・未読アナウンスを各カテゴリ内の先頭に並べる |
| F3-6 | **元DOMノードは複製せず `appendChild` で移設する**（Moodle標準JSのイベントリスナを保つため） |
| F3-7 | `週次（標準）` タブでは元の構造をそのまま表示する |

| カテゴリ | 対象 modtype |
|---|---|
| 授業資料 | `resource` `folder` `url` `page` `book` `label` |
| 課題・テスト | `assign` `quiz` `workshop` |
| アナウンス・フォーラム | `forum` |
| その他 | 上記以外 |

### F4. コースインデックスのツリー化（優先度: 中）

左ドロワーのコースインデックス（`#courseindex` 想定）を、コードエディタのファイルツリーに近い見た目に改める。

| ID | 要件 |
|---|---|
| F4-1 | 活動種別ごとのアイコンを行頭に付与する |
| F4-2 | インデントガイド線（縦罫）で親子関係を可視化する |
| F4-3 | セクション行を太字＋フォルダアイコン、活動行は1段インデント |
| F4-4 | 行高を圧縮し、1画面あたりの情報量を増やす |
| F4-5 | 折りたたみ状態を `localStorage` にコース単位で永続化する |
| F4-6 | 上部にインクリメンタル検索ボックスを設け、入力に応じて行をフィルタする |
| F4-7 | 「すべて展開 / すべて折りたたむ」ボタンを設ける |
| F4-8 | 未読・未提出のある行の右端にドットを表示する |
| F4-9 | 折りたたみ時、セクション内の項目数を表示する |

### F5. 設定画面（優先度: 低）

F1〜F4 の各機能を個別にON/OFFできる。時限の時刻対応表を編集できる。標準ブロック（タイムライン、コース概要、最近アクセス）の非表示可否を選べる。

## 1.4 非機能要件

| ID | 要件 |
|---|---|
| N-1 | Manifest V3。`content_scripts` は ISOLATED world で動作させる |
| N-2 | `world: "MAIN"` は使わない。sesskey はDOMから取得する（`input[name=sesskey]` → 無ければ `a[href*="logout.php?sesskey="]` から正規表現で抽出） |
| N-3 | パーミッションは `storage` と `host_permissions: https://lms.ritsumei.ac.jp/*` のみ |
| N-4 | 外部CDN・外部通信を一切行わない。すべてバンドル内で完結させる |
| N-5 | 1つの機能の例外が他機能を止めないこと（各featureを try/catch で隔離） |
| N-6 | 拡張が無効でもページが壊れないこと（元DOMの破壊的削除を避け、`hidden` 属性またはクラス付与で制御する） |
| N-7 | すべての挿入要素に `rlx-` プレフィックスを付け、Moodle標準のクラス名と衝突させない |
| N-8 | CSSは `document_start` で注入し、書き換え前のちらつきを抑える |
| N-9 | ダッシュボードのタイムライン・コース概要はAJAX後描画のため、`MutationObserver` によるタイムアウト付き待機ユーティリティを共通化する |

## 1.5 想定される反論・リスク

1. **DOM書き換えは壊れやすい**。Moodleのバージョンアップやテーマ更新でセレクタが変わればすぐ機能しなくなる。特に F3 は最も規模が大きく、最も壊れやすい。
2. **F2 の API 依存**。`core_calendar_get_action_events_by_timesort` は Moodle 内部利用を前提としたエンドポイントであり、公開契約ではない。
3. **F1-7（空行・空列の非表示）は情報の欠落を招く**。トグルの既定値は要検討。
4. **F3-6 のDOM移設は、Moodleの `courseformat` JSが保持するノード参照を壊す可能性がある**。初回のみ移設し、以降は表示/非表示で切り替える。
5. **多重適用**。MutationObserverが自身の変更を検知して無限ループに陥る恐れがある。処理済みノードに `data-rlx-done` を付けて冪等性を担保する。

## 2.1 最終的なディレクトリ構成

```
moodle+R_extension/
├── manifest.json
├── README.md
├── docs/
│   ├── REQUIREMENTS.md
│   ├── DOM-NOTES.md
│   └── API-NOTES.md
├── src/
│   ├── content/
│   │   ├── main.js
│   │   └── features/
│   │       ├── timetable.js
│   │       ├── deadlines.js
│   │       ├── course-tabs.js
│   │       └── course-index.js
│   ├── lib/

│   │   ├── wait.js
│   │   ├── moodle-api.js

│   │   ├── modtype.js

│   └── options.js

    ├── icon16.png
```

MV3 の content_scripts は ES Modules に非対応のため、ビルドツールは使わず、
manifest.json の js 配列に依存順で列挙し、各ファイルは `window.RLX` 名前空間に
自分を登録する方式とする。

## 2.2 作成手順（フェーズ順）

- Phase 0: 調査。docs/DOM-NOTES.md と docs/API-NOTES.md を作る
- Phase 1: 基盤（manifest.json, src/lib/*, src/content/main.js, base.css）
- Phase 2: F1 時間割の一覧性
- Phase 3: F2 締切順の課題ブロック
- Phase 4: F4 コースインデックスのツリー化
- Phase 5: F3 コース画面の分類タブ
- Phase 6: F5 設定画面
- Phase 7: 検証

**Phase 0 の結果と本書の想定が食い違った場合は、実装に進まず要件を先に修正すること。**
